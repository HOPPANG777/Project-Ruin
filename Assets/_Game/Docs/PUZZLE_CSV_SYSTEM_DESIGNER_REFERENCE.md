## 0. 엔진을 켜지 않고도 끝나는 작업 경로 (가장 먼저 읽기)

개발을 모르는 기획자도 아래 순서만 지키면, Unity를 열지 않은 채 CSV를 작성해 개발자에게 넘길 수 있습니다.

```text
1) 이 문서로 규칙 이해
2) Project-Ruin_퍼즐_CSV_작성_가이드.xlsx 에서 표 작성
3) 데이터 시트 4장을 각각 CSV UTF-8로 내보내기
4) 파일 이름을 아래와 정확히 맞추기
5) 체크리스트 A(형식 검수) 통과
6) CSV 네 파일 + (선택) xlsx 원본을 개발자에게 전달
```

내보낼 파일 이름은 다음 네 개뿐입니다.

| Excel 시트 | 내보낼 파일 이름 |
| --- | --- |
| `puzzles` | `puzzles.csv` |
| `puzzle_pipe_tiles` | `puzzle_pipe_tiles.csv` |
| `puzzle_light_tiles` | `puzzle_light_tiles.csv` |
| `puzzle_circle_rings` | `puzzle_circle_rings.csv` |

### 0.1 기획자가 혼자 “완료”라고 말해도 되는 기준

다음을 모두 만족하면 형식상 인도 가능합니다.

- 네 CSV의 헤더·열 순서·파일 이름이 문서와 동일하다.
- 부모 `puzzles.csv`와 자식 시트의 `puzzle_id`·종류가 맞다.
- 파이프/라이트는 `rows × columns`개 칸을 빠짐없이 적었다.
- 종류별 필수 규칙(START/END, true/false, `|` 구분, 링 순서 등)을 지켰다.
- 엑셀 작업 원본(`.xlsx`)에서 수정했고, 내보낸 CSV를 다시 엑셀로 열어 저장하지 않았다.

### 0.2 개발자(또는 Unity) 확인이 필요한 기준

다음은 기획자가 CSV만으로 “확실히 끝냈다”고 단정할 수 없습니다. 인도 메모에 함께 적어 주세요.

- 실제로 풀리는지(해답 존재)
- 시작하자마자 클리어되지 않는지
- 화면 밖으로 타일/링이 잘리지 않는지
- 새 Puzzle ID를 문·팝업에 연결했는지
- 원형 `pattern_index`에 해당하는 문양이 Unity에 등록됐는지

> 핵심: 기획자는 **설명서를 정확히 쓰는 사람**이고, Unity는 **설명서를 읽고 조립하는 작업자**입니다. 설명서(CSV)만 완벽하게 쓰면 엔진 없이 넘길 수 있습니다. 조립 결과(플레이 품질) 확인은 개발자 또는 Unity Play가 필요합니다.

## 1. 이 문서를 먼저 읽어야 하는 이유

이 프로젝트의 퍼즐은 Unity 화면에서 타일을 하나씩 배치하는 방식이 아니라, 정해진 CSV 파일에 숫자와 이름을 입력하는 방식으로 내용을 바꿀 수 있습니다.

쉽게 비유하면 다음과 같습니다.

| 실제 역할 | 비유 |
| --- | --- |
| CSV 파일 | 조립 설명서 |
| Excel(`.xlsx`) 가이드 | 설명서를 예쁘게·안전하게 쓰기 위한 작업 노트 |
| Unity | 설명서를 읽고 실제 퍼즐을 조립하는 작업자 |
| 퍼즐 ID | 어떤 설명서를 사용할지 구분하는 제품 번호 |
| 자동 검사 | 설명서에 빠진 부품이나 잘못된 번호가 없는지 확인하는 검수 과정 |
| 게임 화면의 퍼즐 | 설명서에 따라 완성된 결과물 |

기획자는 Unity를 직접 열어 타일 오브젝트를 하나씩 움직이지 않아도 됩니다. CSV에 퍼즐의 크기, 타일 위치, 시작 상태, 클릭 효과 등을 기록하면 게임이 그 내용을 읽어 퍼즐을 만듭니다.

다만 다음 두 문장은 반드시 구분해야 합니다.

> CSV 파일은 Unity가 꺼진 상태에서도 수정할 수 있습니다.

> 수정한 내용이 이미 실행 중인 게임에 실시간으로 즉시 바뀌는 것은 아닙니다.

CSV를 저장한 뒤 프로젝트에 넣고 Unity가 파일을 다시 가져오면 반영됩니다. Unity가 없는 기획자는 CSV를 작성해 넘기기만 하면 됩니다.

## 2. 이번 시스템의 목표

이번 CSV 시스템의 목표는 기획자가 다음 작업을 개발자 도움 없이 처리할 수 있게 하는 것입니다.

- 기존 파이프 퍼즐의 크기와 전체 타일 배치를 변경합니다.
- 파이프의 시작 회전 상태를 변경합니다.
- 기존 라이트 퍼즐의 크기와 각 타일의 시작 상태를 변경합니다.
- 라이트 타일을 클릭했을 때 어떤 타일이 함께 바뀌는지 설정합니다.
- 기존 원형 퍼즐의 링 개수와 시작 회전 상태를 변경합니다.
- 원형 퍼즐에서 Unity에 이미 등록된 문양을 선택합니다.
- 잘못 작성한 값이 있으면 파일명, 줄, 열과 함께 오류를 확인합니다.

반대로 다음 작업은 CSV만으로 끝낼 수 없습니다.

- 완전히 새로운 퍼즐 UI 팝업을 씬에 배치하는 작업
- 새 Puzzle ID를 특정 문이나 오브젝트에 연결하는 작업
- 새로운 이미지나 프리팹을 제작하고 Unity 목록에 등록하는 작업
- 버튼 크기, 타일 간격, 팝업 연출 등 Unity 화면 구성을 바꾸는 작업
- 이미 배포된 실행 파일 옆의 CSV를 바꿔 게임을 실시간 수정하는 작업

CSV는 퍼즐의 **내용 데이터**를 담당합니다. 화면 오브젝트의 연결과 새로운 그래픽 에셋 등록은 Unity 작업입니다.

## 3. CSV가 무엇인가

CSV는 `Comma-Separated Values`의 줄임말입니다. 한국어로 풀면 “쉼표로 값을 나눈 표 형식 파일”입니다.

엑셀 표와 비슷하지만, 실제 파일 안에서는 다음처럼 보입니다.

```csv
puzzle_id,puzzle_type,rows,columns
PIPE_STAGE_01,PIPE,4,4
LIGHT_STAGE_01,LIGHT,3,3
```

### 3.1 CSV의 기본 구성

| 용어 | 쉬운 뜻 | 예시 |
| --- | --- | --- |
| 파일 | 표 한 장을 저장한 문서 | `puzzles.csv` |
| 헤더 | 각 열의 의미를 적은 첫 번째 줄 | `puzzle_id,puzzle_type,rows,columns` |
| 열 또는 Column | 같은 종류의 값이 세로로 모인 칸 | `puzzle_type` 열 |
| 행 또는 Row | 하나의 대상을 설명하는 가로 한 줄 | `PIPE_STAGE_01,PIPE,4,4` |
| 셀 | 행과 열이 만나는 한 칸 | `PIPE` |
| 레코드 | CSV에서 데이터 한 줄을 부르는 말 | 첫 번째 퍼즐 데이터 한 줄 |

CSV의 쉼표는 열을 구분하는 특별한 문자입니다.

```text
PIPE_STAGE_01,PIPE,4,4
       1열      2열 3열 4열
```

따라서 한 칸 안에서 여러 번호를 나열해야 하는 라이트 퍼즐은 쉼표 대신 세로선 `|`를 사용합니다.

```text
1|2|4  →  1번, 2번, 4번
```

### 3.2 CSV와 엑셀 파일은 다르다 (작업은 xlsx, 납품은 csv)

엑셀에서 CSV를 열 수 있지만 CSV와 `.xlsx`는 다른 파일 형식입니다.

| 구분 | CSV | XLSX |
| --- | --- | --- |
| 목적 | 게임이 읽는 최종 납품 파일 | 색상·드롭다운·설명이 있는 작업 원본 |
| 한 파일의 표 | 한 개 | 여러 시트 가능 |
| 색상·테두리·수식 | 저장하지 않음 | 저장 가능 |
| 게임이 읽는 형식 | 예 | 아니요 |

권장 작업 방식:

1. [`Project-Ruin_퍼즐_CSV_작성_가이드.xlsx`](./Project-Ruin_퍼즐_CSV_작성_가이드.xlsx) 에서만 수정합니다.
2. 데이터 시트마다 `다른 이름으로 저장 → CSV UTF-8(쉼표로 분리)` 로 내보냅니다.
3. `.xlsx` 자체를 `Assets/_Game/Data/Csv/` 폴더에 넣지 않습니다.
4. 이미 내보낸 CSV를 다시 엑셀로 열어 저장하지 않습니다. (`true`가 `TRUE`로 바뀌는 등 깨짐이 자주 납니다.)

### 3.3 CSV에서 사용하지 않는 것

- 셀 색상은 게임에 반영되지 않습니다.
- 글자 굵기와 테두리는 게임에 반영되지 않습니다.
- 엑셀 수식은 사용하지 않는 것이 안전합니다.
- 별도 메모 열을 CSV에 포함해 내보내지 않습니다. (가이드 xlsx의 메모 열은 내보내기 대상이 아닙니다.)
- `# 설명` 같은 주석 줄을 넣을 수 없습니다.
- 헤더 위에 제목이나 설명 문장을 추가할 수 없습니다.

기획 메모는 이 Markdown 문서, 가이드 xlsx의 설명 시트, 또는 별도 기획 문서에 작성합니다. 실제 CSV에는 게임이 읽어야 하는 데이터만 둡니다.

### 3.4 엑셀이 값을 마음대로 바꾸는 함정

| 함정 | 증상 | 예방 |
| --- | --- | --- |
| Boolean 대문자화 | `true`가 `TRUE`로 저장됨 | 가이드 xlsx 드롭다운 사용 후 CSV UTF-8로 내보내기 |
| 숫자로 오인 | `01`이 `1`로 바뀜 | ID는 글자로 취급되는 값만 사용 (`PIPE_STAGE_01` 형태) |
| 쉼표 자동 분리 | 영향 ID를 `1,2,4`로 쓰면 열이 늘어남 | 반드시 세로선으로 구분 (`1` `|` `2` `|` `4`) |
| 여러 시트를 한 CSV에 | 저장 실패 또는 한 시트만 저장 | 시트마다 따로 내보내기 |
| 메모 열까지 저장 | 헤더 개수 불일치 오류 | A열부터 데이터 열만 내보내기 |

## 4. 퍼즐 CSV가 게임에 적용되는 전체 흐름

```text
기획자가 CSV 수정 및 저장
→ Unity가 파일 변경을 감지해 TextAsset으로 가져옴
→ GameDataController가 네 개의 퍼즐 CSV를 모음
→ CSV 로더가 표 구조를 읽음
→ 퍼즐 로더가 값과 연결 관계를 검사함
→ GameDataRepository가 Puzzle ID별로 보관함
→ 각 퍼즐 매니저가 자신의 Puzzle ID를 요청함
→ CSV 내용에 따라 타일 또는 링을 생성함
→ 플레이어가 퍼즐을 조작함
```

개발 용어를 기획자 관점에서 풀면 다음과 같습니다.

| 개발 용어 | 기획자가 이해할 의미 |
| --- | --- |
| TextAsset | Unity가 일반 텍스트 파일을 프로젝트 자료로 인식한 형태 |
| Loader | CSV를 읽고 숫자와 이름을 게임이 이해할 데이터로 바꾸는 담당자 |
| Validation | 빠진 값, 잘못된 번호, 중복 좌표 등을 검사하는 과정 |
| Repository | 검사가 끝난 데이터를 Puzzle ID별로 찾아볼 수 있게 보관하는 서랍장 |
| Manager | 보관된 데이터를 받아 실제 퍼즐 화면과 규칙을 작동시키는 담당자 |
| Prefab | Unity에서 미리 만들어 둔 화면 부품의 원본 |
| Inspector | Unity에서 오브젝트의 연결과 설정값을 편집하는 창 |

### 4.1 CSV가 유일한 원본이다

현재 퍼즐 내용의 기준은 다음 네 CSV입니다.

- [`puzzles.csv`](../Data/Csv/puzzles.csv)
- [`puzzle_pipe_tiles.csv`](../Data/Csv/puzzle_pipe_tiles.csv)
- [`puzzle_light_tiles.csv`](../Data/Csv/puzzle_light_tiles.csv)
- [`puzzle_circle_rings.csv`](../Data/Csv/puzzle_circle_rings.csv)

예전에 사용하던 `Stage01.txt` 같은 TXT 파일은 더 이상 퍼즐 원본이 아닙니다. 같은 퍼즐을 TXT와 CSV에 중복 작성하면 어느 파일이 진짜인지 혼란이 생깁니다. 앞으로는 위 네 CSV만 수정합니다.

### 4.2 변경 내용이 반영되는 시점

| 상황 | 반영 방법 |
| --- | --- |
| Unity가 꺼져 있음 | CSV 저장 후 Unity를 열면 가져오기와 검사가 진행됨 |
| Unity가 열려 있고 플레이 중이 아님 | 저장하면 Unity가 파일 변경을 감지해 다시 가져옴 |
| Unity의 Play Mode가 이미 실행 중임 | Play Mode를 종료한 뒤 다시 시작해야 전체 데이터가 확실히 다시 로드됨 |
| 퍼즐 팝업이 이미 열려 있음 | 데이터 재로드 후 팝업을 닫고 다시 열어 퍼즐을 다시 생성해야 함 |
| 이미 빌드된 실행 파일 | 프로젝트 CSV 수정만으로 실행 중인 빌드가 바뀌지 않음 |

가장 안전한 확인 순서는 다음과 같습니다.

1. Play Mode를 종료합니다.
2. CSV를 저장합니다.
3. Unity가 가져오기를 마칠 때까지 기다립니다.
4. Console에 오류가 없는지 확인합니다.
5. Play Mode를 새로 시작합니다.
6. 퍼즐 팝업을 다시 엽니다.

## 5. 네 CSV의 부모와 자식 관계

퍼즐 데이터는 한 파일에 모두 적지 않고 역할별로 나뉩니다.

```text
puzzles.csv
├─ PIPE 퍼즐 → puzzle_pipe_tiles.csv
├─ LIGHT 퍼즐 → puzzle_light_tiles.csv
└─ CIRCLE 퍼즐 → puzzle_circle_rings.csv
```

`puzzles.csv`는 퍼즐의 주민등록부와 같습니다. 퍼즐의 ID, 종류, 기본 크기를 먼저 등록합니다.

나머지 세 파일은 각 퍼즐의 상세 설명서입니다.

| 파일 | 역할 |
| --- | --- |
| `puzzles.csv` | 어떤 퍼즐이 존재하는지 등록 |
| `puzzle_pipe_tiles.csv` | 파이프 퍼즐의 모든 칸 설명 |
| `puzzle_light_tiles.csv` | 라이트 퍼즐의 모든 칸과 클릭 효과 설명 |
| `puzzle_circle_rings.csv` | 원형 퍼즐의 모든 링 설명 |

부모 파일에 없는 `puzzle_id`를 자식 파일에 적으면 오류입니다. 또한 `puzzles.csv`에서 `LIGHT`로 등록한 ID를 파이프 파일에서 사용할 수도 없습니다.

## 6. 모든 CSV에 공통으로 적용되는 규칙

### 6.0 절대 하지 말 것 (한눈에)

| 금지 | 이유 |
| --- | --- |
| 헤더 이름·순서·개수 변경 | 게임이 열을 찾지 못함 |
| 파일 이름·폴더 위치 변경 | 원본 연결이 끊김 |
| CSV에 메모 열·주석 줄·제목 행 추가 | 헤더/열 개수 오류 |
| `True` / `TRUE` / `1` / `켜짐` | Boolean은 `true`/`false`만 |
| 라이트 영향 ID를 쉼표로 구분 | 열이 쪼개짐. `|`만 사용 |
| 파이프/라이트에서 빈 칸 행 생략 | 칸 수 부족 오류 |
| 내보낸 CSV를 엑셀로 다시 열어 저장 | 값 변형 |
| `.meta` 파일 수정·삭제 | Unity 내부 식별 깨짐 |
| 가이드 `.xlsx`를 Csv 폴더에 넣기 | 게임이 읽지 않는 파일 |

### 6.1 헤더는 한 글자도 바꾸지 않는다

첫 번째 줄의 열 이름, 개수, 순서를 정확히 검사합니다.

예를 들어 다음은 모두 서로 다른 것으로 판단됩니다.

```text
puzzle_id       올바름
Puzzle_Id       잘못됨
puzzleId        잘못됨
puzzle_id       뒤에 공백이 있으면 잘못될 수 있음
```

열의 순서를 바꾸거나 임의의 메모 열을 추가해도 오류가 발생합니다.

### 6.2 Puzzle ID 규칙

`puzzle_id`는 퍼즐을 찾기 위한 고유한 이름입니다.

허용 규칙은 다음과 같습니다.

- 첫 글자는 영문 대문자 `A`부터 `Z` 중 하나여야 합니다.
- 이후에는 영문 대문자, 숫자, 밑줄 `_`만 사용할 수 있습니다.
- 같은 ID를 두 번 등록할 수 없습니다.
- 대문자와 소문자를 구분합니다.
- 공백과 한글은 사용하지 않습니다.

| 예시 | 판정 | 이유 |
| --- | --- | --- |
| `PIPE_STAGE_01` | 가능 | 대문자, 숫자, 밑줄만 사용 |
| `LIGHT_ROOM_A` | 가능 | 대문자와 밑줄 사용 |
| `1_PIPE_STAGE` | 불가능 | 첫 글자가 숫자 |
| `Pipe_Stage_01` | 불가능 | 소문자 포함 |
| `PIPE STAGE 01` | 불가능 | 공백 포함 |
| `파이프_01` | 불가능 | 한글 포함 |

ID는 화면에 표시되는 제목이 아닙니다. 개발 시스템이 대상을 정확히 찾기 위한 이름이므로 사람이 보기 좋은 한글 제목 대신 규칙적인 시스템 이름을 사용합니다.

### 6.3 행과 열은 0부터 시작한다

일상에서는 첫 번째를 1이라고 세지만, CSV 좌표는 첫 번째를 0이라고 셉니다.

3 × 3 격자는 다음과 같습니다.

| row \ column | 0 | 1 | 2 |
| ---: | ---: | ---: | ---: |
| 0 | 왼쪽 위 `(0,0)` | 위 가운데 `(0,1)` | 오른쪽 위 `(0,2)` |
| 1 | 왼쪽 가운데 `(1,0)` | 정중앙 `(1,1)` | 오른쪽 가운데 `(1,2)` |
| 2 | 왼쪽 아래 `(2,0)` | 아래 가운데 `(2,1)` | 오른쪽 아래 `(2,2)` |

기억 방법:

> `row`는 위에서 아래로 내려가는 줄 번호입니다.  
> `column`은 왼쪽에서 오른쪽으로 가는 칸 번호입니다.

`rows=3`이면 허용되는 row는 `0, 1, 2`입니다. `row=3`은 네 번째 줄이므로 범위를 벗어납니다.

### 6.4 숫자 작성 규칙

- 정수 칸에는 소수점을 쓰지 않습니다.
- `3.0`, `1.5`, `2칸`처럼 작성하지 않습니다.
- 음수를 허용한다고 명시한 칸 외에는 음수를 쓰지 않습니다.
- 숫자 앞뒤에 설명 문자를 붙이지 않습니다.

### 6.5 참과 거짓 작성 규칙

라이트의 시작 상태는 정확히 다음 두 값만 사용합니다.

```text
true
false
```

`True`, `TRUE`, `False`, `0`, `1`, `켜짐`, `꺼짐`은 사용할 수 없습니다.

### 6.6 빈 줄과 빈칸

- 필수 값은 비워 두지 않습니다.
- 데이터 사이에 의미 없는 빈 줄을 넣지 않는 것이 안전합니다.
- 라이트의 `affected_tile_ids`도 비워 둘 수 없습니다.
- 빈 파이프 칸은 행 자체를 생략하지 않고 `EMPTY`라고 명시합니다.

### 6.7 쉼표, 따옴표, 세로선

표준 CSV는 따옴표로 감싸면 쉼표나 줄바꿈을 한 셀 안에 넣을 수 있습니다. 하지만 퍼즐 데이터에는 그런 복잡한 문자열이 필요하지 않습니다.

기획자가 안전하게 지킬 규칙은 다음과 같습니다.

- 각 열은 쉼표 `,`로만 나눕니다.
- 라이트 영향 ID 목록은 세로선 `|`로 나눕니다.
- 퍼즐 값에 임의로 쉼표나 줄바꿈을 넣지 않습니다.
- 불필요한 큰따옴표 `"`를 추가하지 않습니다.

### 6.8 파일 인코딩

네 CSV는 UTF-8 형식으로 저장합니다. 엑셀에서는 `CSV UTF-8(쉼표로 분리)`를 선택합니다.

인코딩은 글자를 파일에 저장하는 방식입니다. 잘못된 인코딩을 사용하면 한글이 깨지거나 Unity가 파일을 예상과 다르게 읽을 수 있습니다.

### 6.9 파일 이름과 위치

파일 이름과 폴더를 바꾸지 않습니다.

```text
Assets/_Game/Data/Csv/
├─ puzzles.csv
├─ puzzle_pipe_tiles.csv
├─ puzzle_light_tiles.csv
└─ puzzle_circle_rings.csv
```

같은 폴더에 보이는 `.meta` 파일은 Unity가 에셋을 식별하는 내부 표식입니다. 기획자가 직접 열거나 수정하거나 삭제하지 않습니다.

## 7. puzzles.csv 상세 설명

헤더는 다음과 같습니다.

```csv
puzzle_id,puzzle_type,rows,columns
```

### 7.1 열별 의미

| 열 | 쉬운 의미 | 작성 규칙 |
| --- | --- | --- |
| `puzzle_id` | 퍼즐 고유 이름 | 공통 ID 규칙 준수 |
| `puzzle_type` | 퍼즐 종류 | `PIPE`, `LIGHT`, `CIRCLE` 중 하나 |
| `rows` | 세로 줄 개수 | PIPE/LIGHT는 1~100, CIRCLE은 0 |
| `columns` | 가로 칸 개수 | PIPE/LIGHT는 1~100, CIRCLE은 0 |

현재 등록된 데이터는 다음과 같습니다.

```csv
puzzle_id,puzzle_type,rows,columns
PIPE_STAGE_01,PIPE,4,4
LIGHT_STAGE_01,LIGHT,3,3
CIRCLE_STAGE_01,CIRCLE,0,0
```

### 7.2 rows와 columns의 의미

`rows=4`, `columns=4`라면 총 칸 수는 다음과 같습니다.

```text
4 × 4 = 16칸
```

`rows=3`, `columns=5`라면 총 15칸입니다.

이 계산은 파이프와 라이트 자식 CSV에서 필요한 데이터 행 수를 결정합니다.

### 7.3 원형 퍼즐의 크기가 0인 이유

원형 퍼즐은 사각 격자를 사용하지 않고 링 목록을 사용합니다. 따라서 `rows`와 `columns`를 모두 `0`으로 적습니다.

`CIRCLE`에 3과 3을 적거나, `PIPE`에 0과 0을 적으면 오류입니다.

### 7.4 현재 씬에 연결된 ID

현재 `All` 씬의 기존 퍼즐 매니저는 다음 ID를 사용합니다.

| 퍼즐 | 연결된 ID |
| --- | --- |
| 파이프 | `PIPE_STAGE_01` |
| 라이트 | `LIGHT_STAGE_01` |
| 원형 | `CIRCLE_STAGE_01` |

이 ID의 내용을 수정하면 기존 팝업에서 변경 결과를 확인할 수 있습니다.

새 ID를 CSV에 추가하는 것만으로 새 팝업이 자동으로 나타나지는 않습니다. 새 ID를 실제 문, 팝업 또는 퍼즐 매니저에 연결하는 Unity 작업이 한 번 필요합니다.

## 8. 파이프 퍼즐 CSV 상세 설명

파일: [`puzzle_pipe_tiles.csv`](../Data/Csv/puzzle_pipe_tiles.csv)

헤더:

```csv
puzzle_id,row,column,tile_type,rotation
```

### 8.1 열별 의미

| 열 | 쉬운 의미 | 작성 규칙 |
| --- | --- | --- |
| `puzzle_id` | 어떤 파이프 퍼즐의 칸인지 | `puzzles.csv`의 `PIPE` ID |
| `row` | 위에서 아래로 몇 번째 줄인지 | 0부터 `rows - 1` |
| `column` | 왼쪽에서 오른쪽으로 몇 번째 칸인지 | 0부터 `columns - 1` |
| `tile_type` | 칸에 들어갈 파이프 종류 | 정해진 7개 값 중 하나 |
| `rotation` | 기본 모양에서 시계 방향으로 90도 돌린 횟수 | 0, 1, 2, 3 |

### 8.2 사용할 수 있는 타일 종류

| CSV 값 | 화면 의미 | 플레이 중 조작 |
| --- | --- | --- |
| `EMPTY` | 빈 칸 | 파이프가 이동해 들어올 수 있음 |
| `START` | 물의 시작점 | 회전과 이동 불가 |
| `END` | 물이 도착할 목표점 | 회전과 이동 불가 |
| `STRAIGHT` | 양쪽이 연결된 직선 파이프 | 우클릭 회전, 빈 칸으로 드래그 이동 |
| `CORNER` | 두 방향이 꺾여 연결된 파이프 | 우클릭 회전, 빈 칸으로 드래그 이동 |
| `T_JUNCTION` | 세 방향이 연결된 T자 파이프 | 우클릭 회전, 빈 칸으로 드래그 이동 |
| `CROSS` | 네 방향이 연결된 십자 파이프 | 회전해도 연결 방향은 같지만 조작 가능 |

`EMPTY`, `START`, `END`, `STRAIGHT`, `CORNER`, `T_JUNCTION`, `CROSS`를 정확한 대문자로 작성합니다.

### 8.3 회전값 이해하기

회전값은 각도가 아니라 **90도 회전 횟수**입니다.

| rotation | 의미 |
| ---: | --- |
| 0 | 기본 방향 |
| 1 | 기본 방향에서 시계 방향 90도 |
| 2 | 기본 방향에서 시계 방향 180도 |
| 3 | 기본 방향에서 시계 방향 270도 |

각 타일의 `rotation=0` 기준 연결 방향은 다음과 같습니다.

| 타일 | rotation 0의 연결 방향 |
| --- | --- |
| `START` | 위 |
| `END` | 위 |
| `STRAIGHT` | 위 + 아래 |
| `CORNER` | 왼쪽 + 아래 |
| `T_JUNCTION` | 위 + 왼쪽 + 오른쪽 |
| `CROSS` | 위 + 오른쪽 + 아래 + 왼쪽 |
| `EMPTY` | 연결 없음 |

회전값이 1 증가할 때마다 모든 연결 방향도 시계 방향으로 한 칸 이동합니다.

예를 들어 `CORNER`는 다음처럼 바뀝니다.

| rotation | 연결 방향 |
| ---: | --- |
| 0 | 왼쪽 + 아래 |
| 1 | 위 + 왼쪽 |
| 2 | 위 + 오른쪽 |
| 3 | 오른쪽 + 아래 |

### 8.4 반드시 모든 칸을 작성한다

4 × 4 퍼즐이면 정확히 16개의 자식 행이 필요합니다.

- 파이프가 있는 칸만 적으면 안 됩니다.
- 빈 칸도 `EMPTY` 행으로 적습니다.
- 같은 좌표를 두 번 적으면 안 됩니다.
- 좌표 하나를 빠뜨리면 안 됩니다.

### 8.5 START와 END 규칙

한 파이프 퍼즐에는 다음이 정확히 필요합니다.

- `START` 1개
- `END` 1개

0개이거나 2개 이상이면 자동 검사에서 막힙니다.

### 8.6 연결과 클리어 조건

물이 옆 칸으로 이동하려면 서로 맞닿은 두 파이프가 모두 상대 방향으로 열려 있어야 합니다.

예를 들어 왼쪽 칸의 오른쪽이 열려 있더라도 오른쪽 칸의 왼쪽이 닫혀 있으면 연결되지 않습니다.

```text
왼쪽 칸의 오른쪽 열림 + 오른쪽 칸의 왼쪽 열림 = 연결
한쪽만 열림 = 연결 안 됨
```

물은 `START`에서 출발해 연결된 파이프를 따라 퍼집니다. 물이 `END`에 도달하면 클리어됩니다.

모든 파이프를 반드시 사용해야 하는 것은 아닙니다. 사용하지 않은 파이프가 남아 있어도 START와 END가 연결되면 클리어됩니다.

### 8.7 현재 4 × 4 파이프 예시

현재 CSV를 표로 옮기면 다음과 같습니다. 괄호 안 숫자는 회전값입니다.

| row \ column | 0 | 1 | 2 | 3 |
| ---: | --- | --- | --- | --- |
| 0 | START(1) | STRAIGHT(1) | CORNER(0) | EMPTY(0) |
| 1 | T_JUNCTION(3) | CORNER(1) | STRAIGHT(0) | EMPTY(0) |
| 2 | EMPTY(0) | EMPTY(0) | EMPTY(0) | EMPTY(0) |
| 3 | EMPTY(0) | EMPTY(0) | EMPTY(0) | END(3) |

### 8.8 형식 검사는 통과하지만 나쁜 퍼즐이 될 수 있는 경우

자동 검사는 다음을 보장하지 않습니다.

- 실제로 풀 수 있는 배치인지
- 시작하자마자 이미 클리어되는지
- 빈 칸이 충분해 파이프를 이동할 수 있는지
- 해답이 하나인지 여러 개인지
- 난이도가 의도와 맞는지

예를 들어 `EMPTY`가 하나도 없어도 CSV 형식 자체는 통과할 수 있습니다. 하지만 파이프 이동이 불가능해질 수 있으므로 반드시 직접 플레이해야 합니다.

## 9. 라이트 퍼즐 CSV 상세 설명

파일: [`puzzle_light_tiles.csv`](../Data/Csv/puzzle_light_tiles.csv)

헤더:

```csv
puzzle_id,tile_id,row,column,is_on,affected_tile_ids
```

### 9.1 열별 의미

| 열 | 쉬운 의미 | 작성 규칙 |
| --- | --- | --- |
| `puzzle_id` | 어떤 라이트 퍼즐의 칸인지 | `puzzles.csv`의 `LIGHT` ID |
| `tile_id` | 해당 퍼즐 안에서 타일을 부르는 고유 번호 | 1 이상의 정수, 중복 금지 |
| `row` | 위에서 아래로 몇 번째 줄인지 | 0부터 `rows - 1` |
| `column` | 왼쪽에서 오른쪽으로 몇 번째 칸인지 | 0부터 `columns - 1` |
| `is_on` | 퍼즐을 처음 열었을 때 켜져 있는지 | `true` 또는 `false` |
| `affected_tile_ids` | 이 타일을 클릭했을 때 상태가 뒤집히는 타일 목록 | `|`로 구분한 실제 타일 ID |

### 9.2 tile_id와 좌표는 다른 개념이다

`tile_id`는 타일을 부르기 위한 이름표이고, `row`와 `column`은 화면 위치입니다.

| 값 | 역할 |
| --- | --- |
| `tile_id=5` | 클릭 효과에서 5번 타일이라고 참조하기 위한 번호 |
| `row=1,column=1` | 화면 정중앙에 배치하기 위한 위치 |

반드시 `tile_id=5`가 중앙이어야 하는 것은 아닙니다. 하지만 사람이 읽기 쉽도록 왼쪽 위부터 오른쪽 아래까지 1, 2, 3 순서로 붙이는 방식을 권장합니다.

### 9.3 is_on의 의미

| 값 | 시작 상태 |
| --- | --- |
| `true` | 처음 열었을 때 켜짐 |
| `false` | 처음 열었을 때 꺼짐 |

퍼즐을 닫았다가 다시 열어 초기화하면 CSV에 적은 시작 상태로 다시 만들어집니다.

### 9.4 affected_tile_ids의 의미

다음 데이터가 있다고 가정합니다.

```csv
LIGHT_STAGE_01,1,0,0,false,1|2|4
```

뜻은 다음과 같습니다.

- 이 행은 1번 타일을 설명합니다.
- 1번 타일은 왼쪽 위 `(0,0)`에 있습니다.
- 처음에는 꺼져 있습니다.
- 플레이어가 1번 타일을 클릭하면 1번, 2번, 4번 타일 상태가 각각 반전됩니다.

반전은 다음 뜻입니다.

```text
꺼짐 → 켜짐
켜짐 → 꺼짐
```

중요한 점:

> 클릭한 타일이 자동으로 자기 자신을 반전하는 것이 아닙니다.

클릭한 타일도 바꾸려면 자신의 `tile_id`를 `affected_tile_ids`에 직접 포함해야 합니다.

예를 들어 5번 타일을 클릭했을 때 위, 아래, 왼쪽, 오른쪽과 자기 자신을 바꾸려면 다음처럼 적을 수 있습니다.

```text
2|4|5|6|8
```

### 9.5 영향 목록 규칙

- 목록은 비워 둘 수 없습니다.
- 각 번호는 1 이상의 정수여야 합니다.
- 세로선 `|`로 구분합니다.
- 같은 번호를 한 목록에 두 번 적을 수 없습니다.
- 적은 모든 번호가 같은 퍼즐 안의 실제 `tile_id`여야 합니다.
- 다른 라이트 퍼즐의 타일 ID를 참조할 수 없습니다.

| 예시 | 판정 | 이유 |
| --- | --- | --- |
| `1|2|4` | 가능 | 올바른 구분과 양의 정수 |
| `1,2,4` | 불가능 | 쉼표가 CSV 열을 나눔 |
| `1|1|4` | 불가능 | 같은 영향 ID 중복 |
| `0|2|4` | 불가능 | 0은 타일 ID로 사용 불가 |
| `1|2|99` | 조건부 불가능 | 같은 퍼즐에 99번 타일이 없으면 참조 오류 |

### 9.6 반드시 모든 칸을 작성한다

3 × 3 라이트 퍼즐이면 정확히 9개의 타일 행이 필요합니다.

- 모든 좌표를 한 번씩 작성합니다.
- `tile_id`도 각각 하나씩만 사용합니다.
- 같은 좌표에 서로 다른 ID를 두 개 놓을 수 없습니다.

### 9.7 현재 3 × 3 라이트 예시

현재 타일 ID와 시작 상태는 다음과 같습니다.

| row \ column | 0 | 1 | 2 |
| ---: | --- | --- | --- |
| 0 | 1번 꺼짐 | 2번 꺼짐 | 3번 켜짐 |
| 1 | 4번 꺼짐 | 5번 꺼짐 | 6번 꺼짐 |
| 2 | 7번 켜짐 | 8번 꺼짐 | 9번 꺼짐 |

중앙 5번의 영향 목록은 `2|4|5|6|8`입니다. 따라서 5번을 클릭하면 십자 모양의 다섯 타일 상태가 바뀝니다.

### 9.8 클리어 조건

생성된 모든 라이트 타일이 켜지면 클리어됩니다.

자동 검사는 타일과 참조가 올바르게 적혔는지는 확인하지만 다음은 보장하지 않습니다.

- 실제로 모든 불을 켤 수 있는지
- 해답이 존재하는지
- 해답이 너무 짧거나 지나치게 긴지
- 여러 해답 중 의도하지 않은 쉬운 해답이 있는지

라이트 퍼즐은 숫자와 참조가 모두 올바르더라도 수학적으로 풀리지 않을 수 있습니다. 반드시 플레이 테스트가 필요합니다.

## 10. 원형 퍼즐 CSV 상세 설명

파일: [`puzzle_circle_rings.csv`](../Data/Csv/puzzle_circle_rings.csv)

헤더:

```csv
puzzle_id,ring_order,pattern_index,segments,initial_offset
```

### 10.1 열별 의미

| 열 | 쉬운 의미 | 작성 규칙 |
| --- | --- | --- |
| `puzzle_id` | 어떤 원형 퍼즐의 링인지 | `puzzles.csv`의 `CIRCLE` ID |
| `ring_order` | 안쪽부터 몇 번째 링인지 | 0부터 빈 번호 없이 연속 |
| `pattern_index` | Unity에 등록된 문양 목록 번호 | 0 이상의 정수 |
| `segments` | 한 바퀴를 몇 단계로 나눌지 | 2 이상의 정수 |
| `initial_offset` | 정답 위치에서 몇 단계 벗어나 시작할지 | 0이 아니며 `-segments`보다 크고 `segments`보다 작음 |

### 10.2 ring_order 이해하기

링은 안쪽부터 0으로 셉니다.

| ring_order | 위치 |
| ---: | --- |
| 0 | 가장 안쪽 링 |
| 1 | 그다음 바깥 링 |
| 2 | 더 바깥 링 |
| 3 | 네 번째 링 |

번호는 반드시 `0, 1, 2, 3`처럼 빈칸 없이 이어져야 합니다.

`0, 1, 3`처럼 2를 빼먹거나, 같은 번호를 두 번 적으면 오류입니다.

### 10.3 segments 이해하기

`segments`는 한 바퀴 360도를 몇 개의 동일한 단계로 나누는지 정합니다.

```text
한 단계 각도 = 360 ÷ segments
```

| segments | 한 단계 각도 |
| ---: | ---: |
| 4 | 90도 |
| 6 | 60도 |
| 8 | 45도 |
| 12 | 30도 |

플레이어가 링을 드래그한 뒤 놓으면 가장 가까운 단계 각도로 맞춰집니다.

### 10.4 initial_offset 이해하기

정답 위치는 `0`입니다. `initial_offset`은 시작할 때 정답에서 몇 단계 떨어져 있는지 나타냅니다.

`segments=8`이면 한 단계가 45도입니다.

| initial_offset | 시작 차이 |
| ---: | ---: |
| 1 | 한 방향으로 45도 |
| -1 | 반대 방향으로 45도 |
| 2 | 한 방향으로 90도 |
| -2 | 반대 방향으로 90도 |
| 3 | 한 방향으로 135도 |

양수와 음수는 서로 반대 회전 방향입니다. 실제 문양의 기본 방향에 따라 화면 인상이 달라질 수 있으므로 방향이 중요한 디자인은 Unity에서 한 번 확인합니다.

0은 처음부터 정답인 상태이므로 허용하지 않습니다.

`segments=8`일 때 허용 범위는 `-7`부터 `-1`, 그리고 `1`부터 `7`입니다. `-8`, `0`, `8`은 허용되지 않습니다.

### 10.5 pattern_index 이해하기

`pattern_index`는 이미지 파일 이름이 아니라 Unity에 미리 등록된 문양 목록의 순서 번호입니다.

```text
Unity 문양 목록
0번 → 첫 번째 등록 문양
1번 → 두 번째 등록 문양
2번 → 세 번째 등록 문양
```

CSV 검사는 숫자가 0 이상인지 확인합니다. 실제로 그 번호의 문양이 Unity 목록에 존재하는지는 퍼즐을 만들 때 추가로 검사합니다.

현재 `All` 씬의 원형 퍼즐 문양 목록은 0번 사용을 기준으로 연결되어 있습니다. 개발자가 다른 문양 프리팹을 목록에 추가하기 전에는 `pattern_index=0`을 사용해야 안전합니다.

Unity를 열 수 없는 기획자는 다음처럼 처리합니다.

1. 기본값으로 `0`을 사용합니다.
2. 다른 번호가 필요하면 인도 메모에 “pattern_index=N 을 쓰고 싶은데 등록됐는지 확인해 주세요”라고 적습니다.
3. 개발자가 사용 가능한 번호 목록을 알려 주기 전에는 `0` 외 번호를 추측해 넣지 않습니다.

새 그림을 CSV에 넣는 것은 불가능합니다. 다음 두 작업을 구분해야 합니다.

| 작업 | 담당 방식 |
| --- | --- |
| 이미 등록된 문양 중 번호 선택 | CSV |
| 새 문양 이미지 제작 및 Unity 목록 등록 | 아트·개발 Unity 작업 |

### 10.6 현재 원형 퍼즐 예시

현재 데이터는 링 4개이며 모두 `segments=8`입니다. 따라서 한 단계는 45도입니다.

| ring_order | pattern_index | initial_offset | 각도로 해석 |
| ---: | ---: | ---: | ---: |
| 0 | 0 | 1 | 한 방향 45도 |
| 1 | 0 | -2 | 반대 방향 90도 |
| 2 | 0 | 3 | 한 방향 135도 |
| 3 | 0 | -1 | 반대 방향 45도 |

### 10.7 클리어 조건

모든 링의 현재 단계가 0, 즉 정답 방향에 맞으면 클리어됩니다.

자동 검사는 링 번호와 수치 범위는 확인하지만 다음은 보장하지 않습니다.

- 문양이 플레이어에게 방향을 충분히 알려 주는지
- 링이 너무 많아 화면에서 겹치거나 잘리지 않는지
- 난이도가 적절한지
- 시작 상태가 지나치게 단순한지

링의 화면 크기와 링 사이 크기 차이는 Unity의 `startScale`, `scaleStep` 설정입니다. CSV의 링 개수를 크게 늘리면 데이터는 통과해도 화면 밖으로 나갈 수 있으므로 직접 확인해야 합니다.

## 11. 자동 검사가 확인하는 것과 확인하지 못하는 것

### 11.1 자동 검사가 확인하는 것

- 네 CSV 파일이 모두 연결되어 있는지
- 헤더 이름, 개수, 순서가 정확한지
- 필수 값이 비어 있지 않은지
- ID 형식이 올바른지
- 같은 퍼즐 ID가 중복되지 않는지
- 부모와 자식 퍼즐 종류가 일치하는지
- 숫자와 참·거짓 값이 올바른 형식인지
- 좌표가 퍼즐 크기 안에 있는지
- 좌표가 중복되지 않는지
- 파이프와 라이트의 칸 수가 `rows × columns`와 같은지
- 파이프 START와 END가 각각 정확히 하나인지
- 라이트의 영향 ID가 실제로 존재하는지
- 원형 링 순서가 0부터 연속인지
- 원형 링 단계와 시작 오프셋이 허용 범위인지

### 11.2 자동 검사가 확인하지 못하는 것

- 퍼즐이 재미있는지
- 난이도가 의도와 맞는지
- 파이프 퍼즐에 실제 해답이 있는지
- 라이트 퍼즐에 실제 해답이 있는지
- 해답이 하나뿐인지
- 너무 쉽게 우연히 풀리지 않는지
- 원형 문양이 시각적으로 알아보기 쉬운지
- 많은 타일이나 링이 UI 영역 안에 보기 좋게 들어오는지

따라서 작업은 두 단계로 완료됩니다.

```text
1단계: 자동 검사 통과
2단계: 사람이 직접 플레이하여 기획 품질 확인
```

자동 검사 통과는 “문법과 연결이 올바르다”는 뜻이지 “좋은 퍼즐이다”라는 뜻이 아닙니다.

## 12. 오류가 게임을 막는 이유

잘못된 데이터가 있을 때 시스템은 일부 값만 추측해서 실행하지 않습니다.

예를 들어 3 × 3 라이트 퍼즐에 한 칸이 빠졌을 때 시스템이 임의로 꺼진 타일을 만들면 기획자가 작성하지 않은 내용이 게임에 들어갑니다. 이런 자동 보정은 오류를 숨기고 나중에 더 찾기 어렵게 만듭니다.

따라서 시스템은 다음 안전장치를 사용합니다.

| 시점 | 안전장치 |
| --- | --- |
| CSV를 저장해 Unity가 가져올 때 | 자동 검사를 예약하고 오류를 Console에 표시 |
| Play Mode를 시작할 때 | 잘못된 데이터가 있으면 플레이 진입 차단 |
| 게임 빌드를 만들 때 | 잘못된 데이터가 있으면 빌드 차단 |
| 실행 중 데이터를 초기화할 때 | 오류를 기록하고 잘못된 퍼즐 생성 중단 |

이는 기획자를 방해하기 위한 기능이 아니라, 문제가 있는 줄을 배포 전에 정확히 찾기 위한 보호 장치입니다.

## 13. 오류 메시지 읽는 방법

오류 예시는 다음과 같습니다.

```text
[GameDataCsvLoader] source=puzzle_light_tiles, record=4, line=4,
column=affected_tile_ids, message=존재하지 않는 라이트 타일 ID를 참조합니다.
```

| 표시 | 의미 | 기획자가 할 일 |
| --- | --- | --- |
| `source` | 문제가 발견된 CSV 이름 | 해당 파일 열기 |
| `record` | CSV에서 몇 번째 레코드인지 | 해당 데이터 행 주변 확인 |
| `line` | 실제 텍스트 파일의 줄 번호 | 텍스트 편집기 줄 번호로 이동 |
| `column` | 문제가 있는 열 이름 | 해당 열의 값 확인 |
| `message` | 실패 이유 | 안내에 맞게 값 수정 |

보통 첫 줄은 헤더이고 첫 데이터는 2번째 줄입니다. 다만 셀 안 줄바꿈 같은 복잡한 CSV를 사용하면 레코드 번호와 실제 줄 번호가 달라질 수 있으므로 둘 다 표시합니다.

한 번에 첫 번째 오류만 보일 수 있습니다. 첫 오류를 고치고 저장하면 다음 오류가 새로 표시될 수 있습니다. 오류가 없어질 때까지 이 과정을 반복합니다.

## 14. 오류 유형별 원인과 해결 방법

| 오류 또는 증상 | 주된 원인 | 해결 방법 |
| --- | --- | --- |
| CSV 원본이 없음 | 파일 삭제, 이름 변경, Unity 연결 해제 | 원래 파일명과 위치 복구, 개발자에게 연결 확인 요청 |
| 헤더 개수 불일치 | 열 추가 또는 삭제 | 첫 줄을 문서의 정확한 헤더로 복구 |
| 헤더 이름/순서 불일치 | 오타 또는 열 순서 변경 | 이름과 순서를 정확히 복구 |
| 퍼즐 정의가 한 개도 없음 | `puzzles.csv`에 헤더만 존재 | 퍼즐 데이터 행을 한 개 이상 작성 |
| 잘못된 시스템 ID | 소문자, 공백, 한글, 숫자로 시작 | 대문자로 시작하고 대문자·숫자·밑줄만 사용 |
| 중복 퍼즐 ID | `puzzles.csv`에 같은 ID 두 번 작성 | 한 행을 삭제하거나 다른 고유 ID 사용 |
| 알 수 없는 퍼즐 종류 | `PIPE`, `LIGHT`, `CIRCLE` 외 값 | 정확한 종류 이름으로 수정 |
| 격자 크기 오류 | 0, 음수, 100 초과 | PIPE/LIGHT는 1~100 사용 |
| 원형 크기 오류 | CIRCLE의 rows/columns가 0이 아님 | 둘 다 0으로 수정 |
| 부모 퍼즐 없음 | 자식 CSV ID가 `puzzles.csv`에 없음 | 부모 행 추가 또는 ID 오타 수정 |
| 부모 종류 불일치 | LIGHT ID를 파이프 파일에서 사용 | 올바른 자식 CSV로 옮김 |
| 숫자 형식 오류 | 글자, 소수, 빈칸 입력 | 허용되는 정수로 수정 |
| Boolean 오류 | `True`, `1`, `켜짐` 사용 | 소문자 `true` 또는 `false` 사용 |
| 좌표 범위 오류 | row 또는 column이 크기 밖 | 0부터 크기-1 사이로 수정 |
| 중복 좌표 | 같은 퍼즐에 같은 row/column 두 번 작성 | 중복 행 삭제 또는 좌표 수정 |
| 타일 수 오류 | 한 칸 누락 또는 행 과다 | `rows × columns` 수와 모든 좌표 확인 |
| 중복 라이트 ID | 같은 퍼즐에서 tile_id 재사용 | 고유한 양의 정수로 수정 |
| 영향 ID 목록 오류 | 쉼표, 빈 값, 0, 중복 사용 | `1|2|4` 형식으로 수정 |
| 없는 라이트 ID 참조 | 영향 목록의 번호가 실제 타일에 없음 | 실제 tile_id로 수정 또는 해당 타일 추가 |
| 알 수 없는 파이프 타입 | 정해진 7개 값 외 입력 | 정확한 대문자 타입으로 수정 |
| 회전값 오류 | 0~3 밖의 값 | 0, 1, 2, 3 중 하나 사용 |
| START/END 개수 오류 | 없거나 여러 개 | 각각 정확히 한 개 유지 |
| 원형 링 없음 | CIRCLE ID에 자식 행이 없음 | 링을 한 개 이상 작성 |
| 중복 ring_order | 같은 순서 두 번 작성 | 순서를 고유하게 수정 |
| ring_order 불연속 | 0부터 중간 번호가 빠짐 | 0부터 N-1까지 연속 번호 사용 |
| segments 오류 | 0, 1 또는 숫자 아님 | 2 이상의 정수 사용 |
| initial_offset 오류 | 0 또는 허용 범위 밖 | `-segments < 값 < segments`, 0 제외 |
| 문양 프리팹 없음 | pattern_index가 Unity 목록보다 큼 | 현재 등록 번호 사용 또는 개발자에게 프리팹 등록 요청 |
| CSV 열 개수 오류 | 영향 ID를 쉼표로 구분하거나 셀 구조 손상 | 라이트 목록은 `|` 사용, 각 행 열 개수 확인 |

## 15. 기존 퍼즐을 수정하는 안전한 순서

### 15.1 작업 전

1. 수정할 Puzzle ID를 먼저 정합니다.
2. 팀의 최신 파일을 받은 상태인지 확인합니다.
3. 가능하면 Git 작업 브랜치 또는 백업 복사본을 준비합니다.
4. Unity가 Play Mode라면 종료합니다.
5. 같은 CSV를 여러 사람이 동시에 수정하지 않는지 확인합니다.

### 15.2 puzzles.csv 확인

1. 대상 ID가 있는지 찾습니다.
2. `puzzle_type`이 원하는 종류인지 확인합니다.
3. 격자 퍼즐이라면 rows와 columns를 확인합니다.
4. 크기를 바꾼다면 자식 CSV의 전체 좌표도 함께 다시 작성해야 한다는 점을 기억합니다.

### 15.3 자식 CSV 수정

1. 같은 `puzzle_id`의 행만 모아 봅니다.
2. 원본 행을 지우기 전에 새 설계를 표나 종이에 먼저 그립니다.
3. 좌표를 0부터 적습니다.
4. 필수 행 수와 특수 조건을 확인합니다.
5. 다른 Puzzle ID의 행을 실수로 변경하지 않았는지 확인합니다.

### 15.4 저장

1. `CSV UTF-8(쉼표로 분리)` 형식을 선택합니다.
2. 엑셀에서 “일부 기능이 손실될 수 있음” 경고가 나오면 CSV 형식 유지를 선택합니다.
3. `.xlsx` 사본만 저장하고 CSV 저장을 빠뜨리지 않았는지 확인합니다.
4. 파일 이름과 위치가 그대로인지 확인합니다.

### 15.5 Unity 확인 (Unity를 다루는 사람만)

Unity를 열 수 없는 기획자는 15.4까지 마친 뒤 27장의 인도 목록으로 개발자에게 넘기면 됩니다.

1. Unity가 파일을 다시 가져올 때까지 기다립니다.
2. Console의 빨간 오류를 확인합니다.
3. 오류가 있으면 source, line, column, message를 읽고 수정합니다.
4. Play Mode를 새로 시작합니다.
5. `All` 씬에서 숫자 키로 퍼즐을 엽니다.
6. `1`: 파이프, `2`: 라이트, `3`: 원형 퍼즐을 확인합니다.
7. `R` 키 또는 팝업 재열기로 초기 상태가 정확히 복원되는지 확인합니다.
8. 실제로 끝까지 풀어 클리어가 발생하는지 확인합니다.

## 16. 새 퍼즐 데이터를 추가하는 순서

새 Puzzle ID를 등록하는 작업과 게임 공간에 새 퍼즐을 배치하는 작업은 다릅니다.

### 16.1 CSV에서 할 일

1. `puzzles.csv`에 새로운 고유 ID 한 행을 추가합니다.
2. 퍼즐 종류와 크기를 적습니다.
3. 해당 종류의 자식 CSV에 같은 ID의 상세 행을 모두 추가합니다.
4. 파이프와 라이트는 정확히 `rows × columns`개 행을 작성합니다.
5. 종류별 추가 규칙을 모두 확인합니다.
6. 저장 후 자동 검사를 통과시킵니다.

### 16.2 개발자 또는 Unity 작업자가 할 일

1. 새 퍼즐을 보여 줄 팝업 또는 기존 팝업 사용 방식을 결정합니다.
2. 퍼즐 매니저의 `_puzzleId`에 새 ID를 연결합니다.
3. 문, 상호작용 오브젝트 또는 퀘스트 흐름에 팝업을 연결합니다.
4. 필요한 새 프리팹과 그래픽을 등록합니다.

CSV에 새 ID를 추가한 것만으로 플레이어가 그 퍼즐을 만날 수 있는 것은 아닙니다. 데이터는 준비된 상태지만, 실제 게임 공간과 연결하는 마지막 Unity 작업이 필요합니다.

## 17. 기존 퍼즐을 복제해 새 퍼즐을 만드는 방법

완전히 처음부터 작성하는 것보다 검증된 기존 퍼즐을 복제하는 방식이 안전합니다.

### 17.1 공통 절차

1. `puzzles.csv`의 기존 부모 행을 복사합니다.
2. 복사한 행에 새로운 고유 `puzzle_id`를 부여합니다.
3. 해당 자식 CSV에서 기존 ID의 모든 행을 복사합니다.
4. 복사한 모든 자식 행의 `puzzle_id`를 새 ID로 변경합니다.
5. 원하는 배치와 수치를 수정합니다.
6. 이전 ID와 새 ID가 섞인 행이 없는지 검색합니다.

### 17.2 라이트 복제 시 주의

`tile_id`는 프로젝트 전체가 아니라 같은 라이트 퍼즐 안에서만 고유하면 됩니다. 따라서 기존 1~9 번호를 새 퍼즐에서도 다시 사용할 수 있습니다.

모든 `affected_tile_ids`는 같은 새 퍼즐 안의 번호를 참조하므로, 타일 번호 체계를 그대로 복제했다면 영향 목록도 출발점으로 재사용할 수 있습니다.

### 17.3 원형 복제 시 주의

새 문양을 사용할 계획이라면 먼저 그 `pattern_index`가 Unity에 실제로 등록되어 있는지 개발자에게 확인합니다.

## 18. 격자 크기를 바꿀 때의 주의사항

`puzzles.csv`의 rows나 columns만 바꾸면 작업이 끝나지 않습니다.

예를 들어 라이트 퍼즐을 3 × 3에서 4 × 4로 바꾸면 다음이 함께 바뀝니다.

| 항목 | 3 × 3 | 4 × 4 |
| --- | ---: | ---: |
| 필요한 타일 수 | 9 | 16 |
| 허용 row | 0~2 | 0~3 |
| 허용 column | 0~2 | 0~3 |

따라서 다음을 모두 처리해야 합니다.

- 새 좌표 7개를 추가합니다.
- 모든 좌표가 한 번씩 존재하는지 확인합니다.
- 새 라이트 타일에 고유 tile_id를 부여합니다.
- 기존과 새 영향 목록이 실제 ID만 참조하도록 고칩니다.
- 화면 크기 안에 타일이 들어오는지 Unity에서 확인합니다.

크기를 줄일 때도 삭제된 좌표의 타일 ID를 다른 영향 목록이 계속 참조하고 있지 않은지 반드시 확인합니다.

## 19. 엑셀로 편집하는 방법과 주의사항

### 19.1 권장: 가이드 xlsx에서 작업 후 CSV로 내보내기

1. [`Project-Ruin_퍼즐_CSV_작성_가이드.xlsx`](./Project-Ruin_퍼즐_CSV_작성_가이드.xlsx) 를 엽니다.
2. `필독_기본개념` → `파일구조_한눈에` 를 먼저 읽습니다.
3. 파이프/라이트는 `파이프_배치보드` / `라이트_배치보드`에 격자를 먼저 그립니다.
4. `puzzles`와 해당 자식 데이터 시트를 수정합니다. 드롭다운이 있는 칸은 직접 타이핑보다 목록 선택을 사용합니다.
5. 데이터 시트마다 `파일 → 다른 이름으로 저장 → CSV UTF-8(쉼표로 분리)` 로 내보냅니다.
6. “CSV에서는 현재 시트만 저장됩니다” / “일부 기능이 손실될 수 있습니다”가 나오면 CSV 유지를 선택합니다.
7. 파일 이름이 `puzzles.csv` 등과 정확히 같은지 확인합니다.
8. 가이드 xlsx의 메모 열(보통 맨 오른쪽)은 내보내지 않습니다. 데이터 열만 포함된 CSV인지 확인합니다.
9. `✅ 체크리스트` A항목을 모두 확인한 뒤 개발자에게 넘깁니다.

### 19.2 기존 CSV를 직접 열어야 할 때

부득이하게 프로젝트의 `.csv`를 엑셀로 직접 열었다면:

1. 첫 번째 헤더 행을 고정된 계약으로 생각하고 수정하지 않습니다.
2. 필요한 셀만 수정합니다.
3. 저장할 때 반드시 `CSV UTF-8(쉼표로 분리)`를 선택합니다.
4. 저장 후 메모장으로 열어 `true`/`false`가 소문자인지, 헤더가 한 줄인지 확인합니다.

주의할 점:

- 한 CSV에 여러 엑셀 시트를 만들 수 없습니다.
- 셀 병합을 사용하지 않습니다.
- 필터와 색상은 작업 편의를 위해 보일 수 있지만 CSV 자체에는 보존되지 않습니다.
- 자동 번호 변환이나 수식 결과에 의존하지 않습니다.

## 20. Google Sheets로 편집하는 경우

1. CSV를 Google Sheets로 가져옵니다.
2. 한 파일을 한 시트로 관리합니다.
3. 수정 후 `파일 → 다운로드 → 쉼표로 구분된 값(.csv)`을 선택합니다.
4. 내려받은 파일 이름을 프로젝트의 정확한 파일 이름으로 맞춥니다.
5. 올바른 프로젝트 폴더의 기존 CSV를 교체합니다.
6. 열 순서와 헤더가 유지됐는지 확인합니다.

Google Sheets 문서 자체는 게임이 읽지 않습니다. 최종 결과를 `.csv`로 내려받아 프로젝트 파일에 반영해야 합니다.

## 21. 협업과 Git에서 주의할 점

프로젝트 컨벤션에 따라 기획자도 개발자와 같은 브랜치 구조를 사용합니다.

- `release`에 직접 작업하지 않습니다.
- 본인 이니셜 작업 브랜치에서 수정합니다.
- 같은 CSV를 다른 팀원이 동시에 수정하는지 확인합니다.
- CSV와 함께 존재하는 `.meta` 파일을 삭제하거나 다시 만들지 않습니다.
- 오류 확인과 플레이 테스트가 끝난 변경만 공유합니다.

퍼즐 내용 변경의 커밋 메시지 예시는 다음과 같습니다.

```text
[콘텐츠] 파이프 1단계 퍼즐 배치 변경
```

수치 난이도 조정이 핵심이면 다음처럼 작성할 수 있습니다.

```text
[밸런스] 원형 1단계 시작 회전 조정
```

서로 다른 퍼즐을 대규모로 동시에 바꾸기보다 검토 가능한 논리적 단위로 나누는 것이 좋습니다.

## 24. 용어 사전

| 용어 | 뜻 |
| --- | --- |
| CSV | 쉼표로 열을 구분하는 단순 표 파일 |
| Unity | 게임 화면, 에셋, 씬과 실행을 관리하는 게임 엔진 |
| 엔진 | 게임을 만들고 실행하는 기반 프로그램 |
| 데이터 | 퍼즐 크기, 좌표, 상태처럼 게임이 읽는 값 |
| 헤더 | CSV 첫 줄에 적힌 열 이름 |
| 행 | 표의 가로 한 줄 |
| 열 | 표의 세로 구분 |
| 레코드 | CSV의 데이터 한 행 |
| ID | 대상을 다른 대상과 구분하는 고유 이름 또는 번호 |
| Puzzle ID | 하나의 퍼즐 정의를 찾기 위한 고유 이름 |
| 부모 데이터 | 상세 데이터가 속할 대상을 먼저 등록하는 데이터 |
| 자식 데이터 | 부모 ID를 참조해 세부 내용을 설명하는 데이터 |
| Boolean | 참 또는 거짓을 나타내는 값. 이 문서에서는 `true`, `false` |
| 파서 | CSV 문자를 행과 열의 값으로 나누어 읽는 기능 |
| 로더 | 읽은 값을 검사하고 게임용 데이터로 조립하는 기능 |
| 검증 | 값과 연결 관계가 규칙에 맞는지 확인하는 과정 |
| Repository | 검증된 데이터를 ID별로 보관하고 찾아주는 저장소 |
| Manager | 데이터를 사용해 실제 퍼즐을 생성하고 작동시키는 담당 클래스 |
| Prefab | Unity에서 반복 생성할 수 있도록 미리 만든 화면 부품 원본 |
| Inspector | Unity 오브젝트의 값과 참조를 편집하는 창 |
| Scene | 게임 오브젝트와 화면 구성이 배치된 Unity 공간 |
| Play Mode | Unity 안에서 게임을 실행해 시험하는 상태 |
| Console | 오류, 경고, 실행 기록을 보여 주는 Unity 창 |
| TextAsset | Unity가 텍스트 파일을 프로젝트 에셋으로 다루는 형태 |
| `.meta` | Unity가 에셋을 구별하고 참조를 유지하는 내부 식별 파일 |
| Source of Truth | 여러 사본 중 실제 기준으로 사용하는 유일한 원본 |
| Hot Reload | 실행 중인 프로그램이 외부 파일 변경을 즉시 다시 읽는 방식. 현재 배포 게임 퍼즐 CSV에는 적용되지 않음 |

## 25. 기획자가 기억해야 할 핵심 문장

```text
퍼즐 내용의 기준 원본은 네 개의 CSV다.

puzzles.csv는 퍼즐의 ID, 종류, 크기를 등록한다.
나머지 세 CSV는 각 퍼즐의 상세 부품을 적는다.

행과 열은 0부터 센다.
파이프와 라이트는 모든 칸을 빠짐없이 작성한다.

CSV 형식 검사를 통과했다고 반드시 풀리는 퍼즐인 것은 아니다.
자동 검사 후 반드시 직접 플레이한다.

CSV는 Unity를 끈 상태에서도 수정할 수 있다.
하지만 저장 즉시 실행 중인 배포 게임에 실시간 반영되는 방식은 아니다.

새 데이터 ID를 만드는 것은 CSV 작업이고,
그 ID를 게임 속 문이나 팝업에 연결하는 것은 Unity 작업이다.
```

## 27. 개발자에게 넘길 때 첨부할 내용

엔진 없이 작업했다면 아래를 함께 전달하면 인수인계가 매끄럽습니다.

새 ID를 맵에 나타나게 하는 연결, 새 문양 프리팹 등록, Console 오류 해석은 개발자 작업입니다.
