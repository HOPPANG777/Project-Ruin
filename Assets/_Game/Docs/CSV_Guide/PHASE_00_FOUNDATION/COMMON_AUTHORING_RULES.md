# 모든 CSV의 공통 작성 규칙

[README로 돌아가기](../README.md) · [CodeList Master](CODELIST_MASTER.md)

## 1. 시스템 ID

시스템 ID는 게임이 데이터를 찾는 고유 이름입니다.

```text
^[A-Z][A-Z0-9_]*$
```

- 첫 글자는 `A`~`Z` 대문자입니다.
- 이후에는 대문자, 숫자, 밑줄만 사용합니다.
- 대소문자를 구분합니다. `ITEM_COIN`과 `Item_Coin`은 같지 않으며 후자는 형식 오류입니다.
- 같은 범위에서 중복할 수 없습니다. ID에 따라 프로젝트 전체, 같은 부모 안 등 중복 범위가 다릅니다.
- 접두어(`ITEM_`, `QUEST_`, `DLG_`)는 기획 가독성을 위한 권장사항이며, 정규식만 만족하면 로더가 강제하지 않는 경우도 있습니다.

올바른 예: `ITEM_COIN`, `QUEST_RESTORE_MURAL`, `NODE_START`  
잘못된 예: `item_coin`, `ITEM-COIN`, `아이템_코인`, `1ST_ITEM`

## 2. Localization Key

화면 문장을 찾는 Key입니다.

```text
^[a-z][a-z0-9._]*$
```

올바른 예: `item.coin.name`, `dialogue.curator.intro.001`  
잘못된 예: `Item.Coin.Name`, `item-coin-name`, `.item.coin`

이름은 `.name`, 설명은 `.description`처럼 끝내는 방식은 권장 패턴이며 코드가 접미어를 강제하지는 않습니다.

## 3. 중복, 변경, 삭제

- 부모 ID를 바꾸면 모든 자식과 참조 CSV를 함께 바꿔야 합니다.
- `item_id`는 인벤토리 저장 슬롯과 Shop 재고 상태에 사용됩니다.
- Progress Flag ID는 ES3 진행 스냅샷의 문자열 Key가 됩니다.
- `shop_id`와 `item_id` 조합은 저장된 상점 재고 상태 ID에 포함됩니다.
- 출시 후 ID를 바꾸면 기존 저장 데이터가 새 ID를 찾지 못할 수 있습니다. 개발자와 마이그레이션을 검토해야 합니다.
- 삭제 전에는 [ID 변경 영향 지도](../PHASE_07_REFERENCE/ID_CHANGE_IMPACT_MAP.md)에서 참조처를 확인합니다.

## 4. Boolean

허용 값은 정확히 두 개입니다.

- `true`
- `false`

`TRUE`, `False`, `1`, `0`, `O`, `X`, `예`, `아니오`는 허용되지 않습니다. 선택 Boolean은 빈칸이 추가로 허용될 수 있지만, 값이 있으면 소문자 두 값 중 하나여야 합니다.

## 5. 정수와 범위

- `0 이상의 정수`: `0`, `1`, `250`
- `1 이상의 정수`: `1`, `2`, `999`
- 부호 있는 정수: 원형 퍼즐 `initial_offset`만 음수를 허용합니다.
- 소수, 단위가 붙은 문자열, 천 단위 쉼표는 금지합니다.
- C# `int` 범위를 사용하므로 지나치게 큰 숫자는 파싱되지 않습니다. 실무에서는 콘텐츠에 필요한 최소 범위만 사용합니다.

## 6. 필수·선택·조건부의 차이

| 구분 | 의미 | 비우는 방법 |
| --- | --- | --- |
| 필수 | 모든 행에 값 필요 | 비우면 오류 |
| 선택 | 없어도 행이 유효 | 셀을 완전히 비움 |
| 조건부 | 다른 열이나 액션에 따라 함께 입력 또는 함께 비움 | 해당 조합 규칙을 따름 |

빈칸 대신 `NULL`, `NONE`, `없음`, `미정`, `-`를 쓰지 않습니다. 단, `NONE`이 실제 고정 CodeList인 `action_type`에서는 값으로 사용할 수 있습니다.

## 7. 헤더, 파일명, 열 개수

- 헤더를 번역·수정·재정렬하지 않습니다.
- 열을 추가하거나 삭제하지 않습니다.
- 모든 행은 헤더와 같은 열 개수여야 합니다.
- 파일 이름을 변경하지 않습니다.
- 작업용 메모 열은 Excel에만 두고 CSV 내보내기 범위에서 제외합니다.

## 8. UTF-8, 쉼표, 큰따옴표

Project Ruin의 파서는 RFC 4180 방식에 가까운 CSV를 읽습니다.

- UTF-8로 저장합니다. UTF-8 BOM은 첫 문자에서 허용됩니다.
- 쉼표는 열 구분자입니다.
- 쉼표나 실제 줄바꿈이 들어간 셀은 큰따옴표로 감싸야 합니다.
- 셀 안의 큰따옴표는 `""`처럼 두 번 씁니다.
- 닫힌 큰따옴표 뒤에는 쉼표나 줄바꿈만 올 수 있습니다.
- 완전히 빈 물리적 줄은 건너뜁니다. 공백만 있는 행은 빈 줄로 취급되지 않아 열 개수 오류가 날 수 있으므로 만들지 않습니다.

## 9. 문장 줄바꿈

Localization 문장에는 실제 Enter보다 `\n` 두 글자를 권장합니다.

```text
첫째 줄\n둘째 줄
```

로더는 `\n`, `\r`, `\r\n` 표기를 실제 줄바꿈으로 바꿉니다. 리터럴 역슬래시는 `\\`로 적습니다.

## 10. 한 셀에 여러 값

현재 런타임 계약에서 대표적인 복합값은 `puzzle_light_tiles.csv`의 `affected_tile_ids`입니다.

```text
1|2|4
```

이는 `124`가 아니라 1번, 2번, 4번 타일 목록입니다. `|` 양옆 공백은 코드가 정리하지만 새 데이터에는 공백 없이 쓰는 것을 권장합니다. 자세한 작성법은 [조명 퍼즐 시각 가이드](../PHASE_05_PUZZLE/LIGHT_PUZZLE_READABLE_MAPPING.md)를 참고합니다.

## 11. 코드 검증과 기획 권장사항

| 종류 | 예 |
| --- | --- |
| 코드가 강제 | 시스템 ID 문자 규칙, Boolean 소문자, 헤더 순서, 참조 존재, 숫자 최솟값 |
| 기획 권장 | `ITEM_` 접두어, 순서를 0부터 연속 작성, 영향 ID 오름차순, `EMPTY` rotation을 0으로 작성 |

문서에서 “권장”이라고 적은 내용은 어겨도 현재 로더가 즉시 거부하지 않을 수 있습니다. 그래도 사람이 검수하고 장기 유지보수하기 위해 지키는 것이 좋습니다.

## 12. 오류와 경고

- **오류**: CSV 로드나 Repository 생성이 중단됩니다. 헤더 오류, 중복, 필수값 누락, 잘못된 참조가 해당합니다.
- **경고**: 데이터 구조는 읽을 수 있지만 Unity 표시가 불완전할 수 있습니다. 카탈로그에 없는 `icon_id`, `sprite_id`, `background_id`가 대표적입니다.
- 원형 퍼즐 `pattern_index`는 CSV 로더에서 0 이상만 검사하고, 실제 매니저 목록 범위는 퍼즐을 열 때 확인합니다. 잘못되면 런타임 오류 로그가 발생합니다.

검증 방법은 [검증과 문제 해결](../PHASE_08_WORKFLOW_QA/VALIDATION_AND_TROUBLESHOOTING.md)을 참고합니다.
