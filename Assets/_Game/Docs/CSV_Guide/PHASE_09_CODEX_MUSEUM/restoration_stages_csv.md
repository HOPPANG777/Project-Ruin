# restoration_stages.csv

[도감·박물관 가이드](README.md) · [기술](technologies_csv.md)

> 상태: 계획 계약. 현재 단계와 Timeline은 `RelicRestorationCatalogSO`에 있습니다.

## 1. 이 CSV의 목적

문명 재건도가 특정 값에 도달했을 때 진입하는 복원 단계를 정의합니다. 한 행은 **복원 단계 한 개**입니다. Timeline 자체는 Unity 전용 참조이므로 CSV에 파일 경로를 넣지 않고 `stage`를 연결 Key로 사용합니다.

## 2. 언제 작성하는가

재건 단계 수나 단계별 요구 재건도를 바꿀 때 작성합니다. 기술 기여도 총합 100과 마지막 단계 100 정책을 함께 확인해야 합니다.

## 3. 정확한 헤더

```csv
stage,required_restore
```

## 4. 열별 작성 규칙

| 열 이름 | 쉬운 설명 | 필수 여부 | 형식 | 입력 가능 값 | 참조 대상 | 올바른 예 |
| --- | --- | --- | --- | --- | --- | --- |
| `stage` | 1부터 시작하는 복원 단계 번호 | 필수 | 1 이상 정수 | 1부터 빈 번호 없이 연속 | Timeline Catalog | `1` |
| `required_restore` | 이 단계에 진입하는 최소 재건도 | 필수 | 정수 | 1~100, 이전 행보다 큼 | 복원 시스템 | `25` |

## 5. CodeList 및 입력 가능 값

- `stage`: `1, 2, 3...`처럼 1부터 연속입니다.
- `required_restore`: 1 이상 100 이하이며 단계가 올라갈수록 반드시 증가합니다.
- 마지막 행의 `required_restore`는 정확히 `100`입니다.

## 6. 다른 CSV와의 연결

- 의미 연결: `technologies.restore_value` 합계로 현재 재건도를 계산합니다.
- Unity: `stage` → 해당 단계 Timeline을 보관하는 Unity Catalog의 같은 단계 Key
- 저장: 현재 단계 숫자를 별도 진실 원본으로 저장하기보다 반환된 기술의 기여도 합계에서 재계산하는 기존 정책을 우선합니다.

## 7. 작성 순서

1. 필요한 단계 수를 정합니다.
2. 1단계부터 연속으로 행을 작성합니다.
3. 요구 재건도를 오름차순으로 입력합니다.
4. 마지막 단계가 100인지 확인합니다.
5. Unity 담당자에게 각 `stage`의 Timeline 연결을 요청합니다.

## 8. 올바른 예

아래는 형식 설명용이며 실제 단계 확정값이 아닙니다.

```csv
stage,required_restore
1,25
2,60
3,100
```

## 9. 잘못된 예

| 잘못된 값 | 이유 |
| --- | --- |
| 첫 단계가 `0` | 단계는 1부터 시작 |
| `1,25` 다음 `3,60` | 2단계 누락 |
| 요구값 `60` 다음 `60` | 반드시 증가해야 함 |
| 마지막 요구값 `90` | 마지막 단계는 100이어야 함 |
| `timeline_id` 열 추가 | 정확한 헤더 위반; Unity 참조는 단계 Key로 별도 연결 |

## 10. 자동 또는 Unity 검증 항목

Phase 1 구현 시 정확한 2열 헤더, 단계 연속성, 요구값 1~100, 엄격한 오름차순, 마지막 값 100을 오류로 검사합니다. Unity Editor에서는 모든 단계에 Timeline이 연결되었는지 별도로 확인합니다. 현재는 이 CSV용 검증이 구현되지 않았습니다.

## 11. 수정과 삭제 시 주의사항

단계를 삽입하거나 삭제하면 이후 `stage`와 Unity Timeline 연결을 함께 바꿔야 합니다. 요구값 변경은 이미 기술을 반환한 저장에서 로드 직후 적용 단계가 달라질 수 있으므로 연출 재생 정책까지 확인합니다.

## 12. 빠른 체크리스트

- [ ] 마지막 요구값이 100인가?
