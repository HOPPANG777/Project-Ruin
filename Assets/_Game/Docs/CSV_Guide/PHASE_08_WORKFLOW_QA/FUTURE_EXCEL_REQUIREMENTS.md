# 향후 Excel 작성 도구 요구사항

이 문서는 다음 단계에서 Excel 템플릿/검증 도구를 설계하기 위한 요구사항이다. 이번 작업에서는 Excel/CSV 파일이나 내보내기 코드를 만들지 않는다.

## 1. 원칙

- 런타임 계약은 현재 23개 CSV의 정확한 헤더와 값 형식이다.
- Excel은 사람이 편하게 입력하는 UI이며, 내보낸 CSV에 메모/도우미 열을 포함하지 않는다.
- CodeList, 필수/선택, 숫자 범위, 복합키, 교차 참조를 데이터 유효성 검사로 표현한다.
- 매크로가 없어도 검토 가능한 수식/조건부 서식을 우선한다.
- UTF-8, 쉼표 구분, RFC4180 인용, 소문자 Boolean을 보장한다.

## 2. 워크북 구성 제안

| 시트 그룹 | 목적 |
|---|---|
| README/Export | 버전, 내보내기 순서, 오류 요약 |
| CodeLists | 고정 enum과 동적 ID 목록 |
| 23개 원본 시트 | CSV 한 파일당 정확한 런타임 열 |
| LightPuzzleView | ID/시작 상태/영향 체크박스 가독성 화면 |
| Validation | 중복, 누락 참조, 범위 오류 집계 |
| ChangeImpact | 변경/삭제 ID와 참조 위치 표시 |

도우미 시트는 CSV로 내보내지 않는다.

## 3. 공통 유효성 검사

- 시스템 ID/로컬라이제이션 키 정규식에 준하는 수식 검사
- 정확한 `true`/`false` 드롭다운
- 고정 CodeList 드롭다운
- 부모 ID 동적 드롭다운
- 필수 셀 공백 표시
- 전역 및 부모 범위 복합키 중복 표시
- 0 이상/1 이상/상한 포함 숫자 검사
- 조건부 쌍(보상 플래그/아이템) 완전성
- 행의 런타임 열 외 값이 export에 포함되지 않도록 열 매핑 고정

## 4. 시스템별 편집 지원

### 대화

- 그래프를 선택하면 같은 그래프 노드만 다음 노드 후보로 표시
- 배우를 선택하면 해당 배우 초상화만 후보로 표시
- 액션 종류에 따라 action ID 후보와 next/action 공백 규칙 변경
- 선택지가 있는 노드의 `next_node_id` 경고

### 퀘스트

- 부모 퀘스트 선택에 따른 목표/보상/소비 그룹 필터
- 순서/ID 중복 경고
- 소비 아이템이 있으면 자동 완료 흐름 주의 표시
- 진행 플래그 입력은 현재 대문자 시스템 ID 계약을 사용
- `skill.acquired.` 형태는 계약 변경 전 허용하지 않음

### 퍼즐

- 보드 크기에 따른 좌표 자동 생성/누락 표시
- PIPE 타일 방향 미리보기와 현재 회전표
- LIGHT 시작 상태 체크박스와 클릭×영향 행렬
- LIGHT 타일 생성 시 해당 타일의 영향 체크 행과 영향 대상 열을 동시에 자동 생성
- CIRCLE 장면별 패턴 배열 목록을 수동/자동 동기화할 인터페이스
- 해결 가능성 검사는 별도 명시 기능으로 취급하고, 현재 런타임 검증으로 오인하지 않음

### 상점

- 통화 후보는 `can_sell=false` 아이템만
- 상품 후보는 통화 제외, `can_sell=true` 및 `price>0`만
- `initial_stock=0`에 ‘시작 품절’ 경고

## 5. LIGHT 퍼즐 변환 규칙

사용자는 영향 행렬에서 체크하고, 내보내기는 체크된 타일 ID를 `|`로 연결한다. `affected_tile_ids` 원문 문자열은 읽기 전용 미리보기로 제공하며 기본 입력칸으로 사용하지 않는다.

```text
체크된 ID: 1, 2, 4
내보낸 셀: 1|2|4
```

- 오름차순 정렬 권장
- 중복 제거
- 최소 한 개 필요
- 자기 체크 여부를 명시적으로 표시
- CSV에는 6열만 내보냄

### 5.1 타일 생성 이벤트

같은 퍼즐에 LIGHT 타일 하나가 생성되는 즉시 다음 작업을 한 번에 수행한다.

1. 타일 기본 데이터 행을 만든다.
2. 새 타일을 클릭 원본으로 하는 영향 체크리스트 행을 만든다.
3. 새 타일을 영향 대상으로 하는 체크리스트 열을 만든다.
4. 기존 모든 클릭 타일 행에 새 타일 체크 항목을 추가한다.
5. 새 체크리스트의 머리글에 타일 ID와 `(row,column)` 좌표를 표시한다.
6. 새 체크는 미선택으로 초기화한다.
7. 새 타일 행에서 한 개 이상 선택할 때까지 미작성 오류와 내보내기 차단 상태를 표시한다.

첫 번째 타일을 만들면 자기 자신 한 개를 대상으로 하는 체크리스트가 생긴다. 두 번째 타일을 만들면 두 타일 모두 `2×2`, 세 번째 타일을 만들면 `3×3` 영향 행렬에서 편집할 수 있어야 한다. 퍼즐에 타일이 `N`개라면 항상 `N×N` 영향 행렬이어야 한다.

### 5.2 타일 수정·삭제 이벤트

- 타일 ID 또는 좌표가 바뀌면 행·열 머리글과 보드 표시가 즉시 갱신된다.
- ID 변경 전 체크 상태는 해당 타일 데이터와 함께 유지한다.
- 타일을 삭제하면 해당 클릭 행과 영향 대상 열을 함께 제거한다.
- 삭제 타일을 영향 대상으로 체크한 기존 행은 영향을 받는 클릭 타일 목록을 경고로 보여 준 뒤 사용자가 확인하도록 한다.
- 다른 퍼즐의 타일은 체크 후보에 절대 섞지 않는다.

### 5.3 체크 결과와 내보내기

- 체크 한 개는 “이 행의 타일을 클릭하면 이 열의 타일 상태를 반전한다”는 뜻이다.
- 자기 자신도 자동 토글되지 않으므로 대각선 자기 체크도 명시적으로 선택한다.
- 체크 결과는 타일 ID 오름차순, 중복 없는 `|` 문자열로 자동 변환한다.
- 체크 행렬, 영향 보드, 읽기 전용 `affected_tile_ids` 미리보기는 항상 같은 상태를 보여야 한다.
- 기획자가 `|` 문자열을 직접 수정해야만 작업이 가능한 UI는 수용하지 않는다.

관계를 별도 행으로 내보내는 `puzzle_light_tile_effects.csv`는 미래 스키마 제안이며, 로더/저장소/테스트/문서 계약을 함께 바꾸는 별도 프로젝트 승인 전에는 생성하지 않는다.

## 6. 내보내기 전 차단 조건

- 정확한 헤더와 열 순서 불일치
- 필수값 공백
- ID/키 형식 오류
- 중복 키 또는 누락 참조
- 잘못된 CodeList/Boolean/숫자 범위
- 퍼즐 좌표/링 불완전
- 액션 조건부 규칙 위반
- 내보내기 대상에 메모 열 포함

경고로만 둘 항목과 차단 오류를 구분한다. 에셋 카탈로그 누락, 실제 장면 NPC, 퍼즐 해결 가능성처럼 Excel만으로 확정할 수 없는 것은 수동 QA 목록으로 보낸다.

## 7. 버전/추적성

- 워크북 템플릿 버전과 지원하는 CSV 스키마 버전 기록
- 내보낸 파일명, 행 수, 시간, 오류 0건 여부 기록
- ID 변경 목록과 영향 검색 결과 기록
- 원본 시트와 내보낸 CSV의 행 해시 또는 비교 기능 고려
- Excel이 정수/Boolean을 로캘 의존 문자열로 바꾸지 않도록 고정

## 8. 수용 기준

- 23개 CSV 모두 정확한 헤더로 내보낼 수 있다.
- 현재 원본 데이터를 왕복해 의미 있는 값 변화가 없다.
- 잘못된 예시를 입력하면 해당 셀/행이 차단 또는 경고된다.
- LIGHT 영향 행렬과 `|` 셀이 양방향으로 일치한다.
- LIGHT 타일 한 개를 생성하면 체크 행과 체크 열이 별도 조작 없이 즉시 생긴다.
- LIGHT 타일이 `N`개일 때 같은 퍼즐의 영향 행렬이 항상 `N×N`이다.
- LIGHT 타일 추가·수정·삭제 후 행렬, 좌표 보드, 내보내기 미리보기에 오래된 ID가 남지 않는다.
- 한 개 이상의 영향이 선택되지 않은 LIGHT 타일은 내보내기가 차단된다.
- Unity 저장소 회귀 검증을 통과한다.
- 사용자 메모는 CSV에 유출되지 않는다.
