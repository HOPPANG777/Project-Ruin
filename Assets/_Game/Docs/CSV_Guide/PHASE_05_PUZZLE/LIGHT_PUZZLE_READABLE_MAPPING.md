# LIGHT 퍼즐 읽기용 매핑

이 문서는 현재 `puzzle_light_tiles.csv`의 3×3 LIGHT 퍼즐을 사람이 검토하기 쉽게 펼친 보조 자료다. 런타임 원본은 CSV이며 이 문서가 데이터를 대체하지 않는다.

## 1. 읽는 법

- 좌표는 `(row,column)`, 0 기반이다.
- `◎`: 클릭한 칸이면서 영향 목록에도 포함
- `●`: 영향받는 다른 칸
- `○`: 클릭한 칸이지만 영향 목록에는 없음
- `·`: 영향 없음
- 클릭한 칸도 자동으로 바뀌지 않는다. `affected_tile_ids`에 있을 때만 토글된다.

## 2. 현재 타일 ID 그리드

| row\column | 0 | 1 | 2 |
|---:|---:|---:|---:|
| 0 | 1 | 2 | 3 |
| 1 | 4 | 5 | 6 |
| 2 | 7 | 8 | 9 |

## 3. 현재 시작 상태

`ON`은 켜짐, `off`는 꺼짐이다.

| row\column | 0 | 1 | 2 |
|---:|:---:|:---:|:---:|
| 0 | off | off | ON |
| 1 | off | off | off |
| 2 | ON | off | off |

## 4. 현재 원본 행 확장표

| tile_id | 좌표 | 시작 | CSV 원문 `affected_tile_ids` | 사람이 읽는 영향 |
|---:|---|:---:|---|---|
| 1 | (0,0) | off | `1|2|4` | 자신, 오른쪽, 아래 |
| 2 | (0,1) | off | `2|3|5` | 자신, 오른쪽, 아래 |
| 3 | (0,2) | ON | `3|6` | 자신, 아래 |
| 4 | (1,0) | off | `1|4|5|7` | 위, 자신, 오른쪽, 아래 |
| 5 | (1,1) | off | `2|4|5|6|8` | 위, 왼쪽, 자신, 오른쪽, 아래 |
| 6 | (1,2) | off | `3|5|6|9` | 위, 왼쪽, 자신, 아래 |
| 7 | (2,0) | ON | `4|7|8` | 위, 자신, 오른쪽 |
| 8 | (2,1) | off | `5|7|8|9` | 위, 왼쪽, 자신, 오른쪽 |
| 9 | (2,2) | off | `6|8|9` | 위, 왼쪽, 자신 |

## 6. 사람이 검토하는 순서

1. `puzzles.csv`에서 LIGHT 퍼즐의 `rows`, `columns`를 확정한다.
2. 0 기반 좌표 그리드를 그린다.
3. 모든 칸에 1 이상의 고유 `tile_id`를 배정한다.
4. 시작 상태를 별도 ON/off 그리드에 표시한다.
5. 타일 생성과 동시에 해당 타일의 영향 체크리스트가 생겼는지 확인한다.
6. 클릭 타일 행에서 영향받을 타일을 체크한다.
7. 체크 결과가 영향 보드에 같은 모양으로 표시되는지 확인한다.
8. 체크된 ID가 오름차순 `|` 목록으로 자동 변환되는지 확인한다.
9. 자기 자신을 토글할 의도라면 자기 ID 체크 여부를 확인한다.
10. 모든 ID가 같은 퍼즐에 존재하고 한 목록에서 중복되지 않는지 확인한다.
11. 모든 좌표가 정확히 한 번인지 확인한다.
12. 시작 상태에서 실제로 클리어 가능한지 PlayMode로 검증한다.

## 7. 자주 생기는 오류

| 잘못된 값/가정 | 문제 | 수정 |
|---|---|---|
| `1,2,4` | CSV 열 구분자와 충돌하며 내부 목록 형식도 아님 | `1|2|4` |
| `1|1|2` | 한 영향 목록의 중복 | `1|2` |
| `1|2|99` | 같은 퍼즐에 없는 타일 | 유효한 ID로 교체 |
| `is_on=0` | 현재 Boolean 규칙 위반 | `false` |
| 자기 ID를 빼고도 클릭 칸이 바뀐다고 예상 | 자동 자기 토글 없음 | 의도하면 자기 ID 추가 |
| 그리드 일부 행 생략 | `rows*columns` 완전성 실패 | EMPTY 개념 없이 모든 칸 작성 |

## 8. 현재 CSV와 향후 Excel 작성 화면

현재 런타임 계약은 한 셀에 `affected_tile_ids`를 `|`로 저장하는 6열 CSV다. 그러나 이 문자열은 런타임 내보내기 형식일 뿐, 기획자의 기본 입력 방식으로 사용하지 않는다.

향후 Excel 작성 화면은 다음 요소를 반드시 제공한다.

- 좌표/타일 ID 그리드
- 시작 상태 체크박스
- 클릭 타일별 영향 체크 행렬
- 중복, 자기 포함 여부, 존재하지 않는 ID, 좌표 누락 경고
- `affected_tile_ids` 읽기 전용 내보내기 미리보기

### 타일 생성 시 자동 확장 규칙

LIGHT 타일 하나는 동시에 두 역할을 가진다.

- 클릭할 수 있는 원본 타일
- 다른 클릭의 영향을 받을 수 있는 대상 타일

따라서 타일이 하나 추가되면 영향 행렬에 **행과 열이 각각 하나씩** 자동으로 추가되어야 한다. 새 행은 새 타일을 클릭했을 때의 체크리스트이고, 새 열은 기존 타일을 클릭했을 때 새 타일도 영향을 받을지 선택하는 항목이다.

예를 들어 1~4번 타일이 있는 상태에서 5번 타일을 추가하면 다음 구조로 즉시 확장한다.

| 클릭 타일 ↓ / 영향 타일 → | 1 | 2 | 3 | 4 | 새 타일 5 |
|---:|:---:|:---:|:---:|:---:|:---:|
| 1 | 기존 | 기존 | 기존 | 기존 | 새 체크 |
| 2 | 기존 | 기존 | 기존 | 기존 | 새 체크 |
| 3 | 기존 | 기존 | 기존 | 기존 | 새 체크 |
| 4 | 기존 | 기존 | 기존 | 기존 | 새 체크 |
| 새 타일 5 | 새 체크 | 새 체크 | 새 체크 | 새 체크 | 새 자기 체크 |

각 머리글과 체크 항목은 `5 (1,1)`처럼 타일 ID와 좌표를 함께 표시한다. 새 체크는 미선택으로 시작하고, 새 타일 행에서 하나 이상의 영향을 선택하기 전까지 미작성 오류를 표시한다. 선택된 체크는 오름차순으로 결합하여 `2|4|5|6|8` 같은 결과를 자동 생성한다.

그러나 내보내는 런타임 CSV는 반드시 현재 6열 헤더와 `1|2|4` 형식을 유지해야 한다. 주석/메모 열은 내보내지 않는다.

장기적으로 관계를 정규화해야 한다면 다음 별도 파일을 제안할 수 있다.

```csv
puzzle_id,source_tile_id,affected_tile_id
```

가칭 `puzzle_light_tile_effects.csv`는 **미래 제안일 뿐**이며 현재 프로젝트에 만들거나 로더 계약을 바꾸지 않는다.

## 9. 검증 경계

자동 검증은 좌표 수·중복·범위, 타일 ID, 영향 참조를 잡는다. 초기 상태에서 모든 불을 켤 수 있는지에 대한 선형대수/탐색 기반 해결 가능성 검사는 현재 구현되어 있지 않다. 따라서 최소한 다음을 PlayMode에서 확인한다.

- 아홉 클릭이 표와 동일한 칸을 토글한다.
- 자기 ID가 있는 클릭은 자신도 토글한다.
- 시작 상태가 CSV와 동일하다.
- 모든 타일이 ON일 때 클리어 처리된다.
- 씬을 다시 열거나 저장을 복원했을 때 의도한 상태가 된다.
