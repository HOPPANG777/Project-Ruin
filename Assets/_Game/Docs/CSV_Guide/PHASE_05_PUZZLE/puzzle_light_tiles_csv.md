# puzzle_light_tiles.csv 작성 가이드

## 1. 목적

LIGHT 퍼즐의 각 좌표·타일 ID·초기 점등 상태와 클릭 시 토글할 타일 목록을 정의한다.

## 2. 언제 작성하는가

부모 LIGHT 퍼즐의 크기를 정한 뒤 작성한다. 영향 관계는 숫자를 `|`로 직접 입력해 설계하지 않는다. 먼저 타일 ID가 보이는 보드와 `클릭 타일 × 영향 타일` 체크리스트에서 설계하고, `affected_tile_ids`는 체크 결과로 자동 생성한다.

현재 런타임 CSV를 직접 수정해야 하는 경우에만 체크 결과와 동일한 숫자 목록을 수동으로 옮긴다. 이 방식은 임시 작업 절차이며, 향후 Excel 작성 화면에서는 수기 입력을 기본 작업으로 제공하지 않는다.

## 3. 정확한 헤더

```csv
puzzle_id,tile_id,row,column,is_on,affected_tile_ids
```

## 4. 열 규칙

| 열 | 필수 | 형식/검증 |
|---|---:|---|
| `puzzle_id` | 예 | 존재하며 LIGHT인 퍼즐 |
| `tile_id` | 예 | 1 이상 정수, 퍼즐 안에서 유일 |
| `row` | 예 | 0 이상, 부모 행 수 미만 |
| `column` | 예 | 0 이상, 부모 열 수 미만 |
| `is_on` | 예 | `true` 또는 `false` |
| `affected_tile_ids` | 예 | 체크리스트에서 선택한 타일 ID를 `|`로 결합한 자동 생성 값 |

모든 좌표가 정확히 한 번 있어야 하고 행 수는 `rows*columns`다. 영향 ID는 같은 퍼즐에 존재해야 하며 한 셀 안에서 중복할 수 없다.

## 5. CodeList

Boolean은 소문자 `true`/`false`. 영향 목록은 예: `1|2|4`. `|`는 계산 기호가 아니라 여러 타일 ID를 한 CSV 셀에 저장하기 위한 런타임 구분자다. 공백은 트림되지만 내보낼 때 공백 없이 쓴다.

## 6. 연결 관계

`puzzles.csv`의 LIGHT 부모를 참조하고, `affected_tile_ids`는 같은 퍼즐의 `tile_id`를 참조한다. 클릭한 타일은 자동 토글되지 않는다. 자기 자신도 바꾸려면 목록에 자기 ID를 명시한다.

## 7. 기획자 작성 화면의 기본 형태

기획자는 먼저 실제 배치와 같은 ID 보드를 본다.

```text
1  2  3
4  5  6
7  8  9
```

영향 관계는 다음과 같은 체크리스트에서 선택한다. 행은 **클릭한 타일**, 열은 **상태가 바뀔 타일**이다.

| 클릭 타일 ↓ / 영향 타일 → | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 자동 생성 결과 |
|---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|---|
| 1 | ✓ | ✓ |  | ✓ |  |  |  |  |  | `1|2|4` |
| 5 |  | ✓ |  | ✓ | ✓ | ✓ |  | ✓ |  | `2|4|5|6|8` |

예를 들어 5번 행의 체크는 다음 보드와 같은 뜻이다.

```text
·  ✓  ·
✓  ✓  ✓
·  ✓  ·
```

기획자는 체크만 편집한다. `1|2|4`, `2|4|5|6|8` 같은 값은 확인용 미리보기이며 직접 작성하는 입력칸이 아니다.

## 8. 향후 Excel에서 타일을 생성할 때의 필수 동작

LIGHT 퍼즐 타일 하나를 생성하면 같은 퍼즐 안에서 다음 항목이 즉시 함께 생성되어야 한다.

1. `tile_id`, 좌표, 초기 상태를 입력하는 타일 기본 행
2. 새 타일을 클릭 대상으로 하는 영향 체크리스트 한 행
3. 새 타일을 영향 대상으로 선택할 수 있는 체크리스트 한 열
4. 타일 ID와 좌표가 함께 표시되는 체크 항목
5. 체크 결과를 변환한 `affected_tile_ids` 읽기 전용 미리보기
6. 최소 한 개 미선택, 존재하지 않는 타일, 중복 ID 및 좌표에 대한 오류 표시

예를 들어 기존 타일이 `1~4`일 때 5번 타일을 추가하면 다음 두 변화가 동시에 일어나야 한다.

- 5번 클릭의 영향 대상을 고르는 `1, 2, 3, 4, 5` 체크리스트가 새로 생긴다.
- 기존 1~4번 클릭 체크리스트에도 영향 대상 `5`가 자동으로 추가된다.

체크 항목은 숫자만 보여 주지 않고 `5 (row 1, column 1)`처럼 ID와 좌표를 함께 표시해야 한다. 새 체크는 기본적으로 미선택 상태로 만들고, 자기 자신을 토글하려면 자기 ID 항목도 기획자가 명시적으로 체크한다. 아무 항목도 선택하지 않은 타일은 미작성 오류로 표시하고 내보내기를 차단한다.

타일 ID를 바꾸거나 타일을 삭제하면 체크리스트의 행·열·표시명과 자동 생성 결과가 함께 갱신되어야 한다. 삭제되는 타일을 선택하고 있던 체크가 있다면 조용히 지우지 않고 영향받는 클릭 타일을 경고로 보여 준다.

## 9. 작성 순서

1. 좌표별 고유 타일 ID 표를 만든다.
2. 초기 상태 그리드를 만든다.
3. 각 타일 생성과 동시에 생긴 영향 체크리스트를 확인한다.
4. 각 클릭으로 바뀔 칸을 체크한다.
5. 시각 보드와 자동 생성된 `affected_tile_ids` 미리보기가 일치하는지 확인한다.
6. 전 좌표/참조/중복을 검사한다.
7. 런타임 CSV로 내보낸다.
8. 각 클릭과 클리어 가능성을 PlayMode에서 확인한다.

## 10. 유효 예시

```csv
PUZZLE_LIGHT_A,1,0,0,false,1|2|4
PUZZLE_LIGHT_A,2,0,1,false,2|3|5
```

## 11. 잘못된 예시

| 값 | 이유 |
|---|---|
| `is_on=1` | Boolean은 `true`/`false` |
| `affected_tile_ids=1,2,4` | 구분자는 쉼표가 아니라 `|` |
| `1|1|2` | 같은 셀의 영향 ID 중복 |
| 존재하지 않는 ID `99` | 같은 퍼즐 참조가 아님 |
| 자기 ID 누락을 자동 토글로 기대 | 런타임은 목록만 토글함 |
| 기획자가 `2|4|5|6|8`을 기본 입력 화면에서 직접 작성 | 체크 실수와 의미 파악이 어려움. 영향 체크리스트에서 선택하고 자동 생성해야 함 |

## 12. 자동/Unity 검증

저장소가 부모 종류, 전 좌표 완전성, 타일/좌표 중복, Boolean, 영향 목록의 양의 정수·중복·실재를 검사한다. 수학적 해결 가능성은 검사하지 않는다. 모든 시작 상태와 클릭 효과를 PlayMode에서 검증한다.

## 13. 수정·삭제 주의

타일 ID를 바꾸면 다른 모든 행의 영향 목록을 함께 고쳐야 한다. 행 삭제는 좌표 완전성과 참조를 모두 깨뜨릴 수 있다. 현재 결합 목록 스키마를 임의로 여러 열로 바꾸지 않는다.

## 14. 빠른 체크리스트

- [ ] 전 좌표가 한 번씩 있고 타일 ID가 유일하다.
- [ ] Boolean이 소문자다.
- [ ] 모든 타일에 클릭 영향 체크리스트가 자동 생성되었다.
- [ ] 타일 추가·삭제 시 영향 행과 열이 함께 갱신되었다.
- [ ] 체크 결과와 `|` 자동 생성 미리보기가 일치한다.
- [ ] 자기 토글이 필요하면 자기 ID가 들어 있다.
- [ ] 해결 가능성을 직접 확인했다.
